# Virtual Families 1: divide-by-zero audit

Every integer division (`div`, `idiv`, every operand form) in the code of the vanilla `Virtual Families.exe`
(1.01.00) that the game can run, with where its divisor comes from and whether it can be 0 in play.

## Method

* **Which code can run.** Recursive descent from the entry point, the same method as the research `reach.py`:
  direct calls, jumps and branches, jump tables, code addresses the code takes (`push` / `mov` of a code address),
  virtual methods of every class whose vtable reachable code stores (a class that is made), and the C runtime's
  static-initializer tables (`_initterm` 0x4B2464..0x4B2540, 0x4B2544..0x4B2560).
  `tests/test_divide_by_zero_audit.py` repeats that walk on the vanilla exe and checks that the divisions it finds
  are exactly the sites in the table below, so a missed or extra site fails the test.
* **What it finds.** 211 divisions: 156 in the game's own code
  (below 0x497848) and 55 in the statically linked C runtime. None is
  skipped: the C runtime's divisions are listed too, each with its constant or its check.
* **64-bit division helpers.** `_aulldiv` 0x49E330, `_alldiv` 0x49EC80, `_aullrem` 0x49ED40 and `_aulldvrm` 0x4A8650
  are the only ones (no `_allrem`). Every call to them is in the C runtime's time and `printf` code, with constant
  divisors; no game code calls them.
* **Random ranges.** GetRandom 0x403650 (`rand() % n`) divides only when n is 1..0x7FFF (0x403658..0x403660);
  any other n takes 0x403671..0x4036C5, which has no integer division and returns 0 for n <= 0. So none of its
  5,085 callers can make it divide by 0 (one passes 0, 0x47A1EA, and the rain's respawn passes -561, 0x491DF0:
  both get 0). Proved by emulation in `tests/test_divide_by_zero_audit.py`.
* **Classes.** SAFE-CONSTANT: the divisor is a constant (or always one of a few constants). GUARDED: the code
  checks the divisor (or what it is made from) first; the check is named. UNREACHABLE-ZERO: the divisor comes from
  game values, but it cannot be 0 in play; the proof is given. REACHABLE-CRASH: emulated to fault, and a real
  family can reach it.
* **Evidence.** "emulated" names the test that runs the game's own code in Unicorn; "read" means proved from the
  disassembly (addresses given).

## Summary

| Class | Sites |
|---|---|
| SAFE-CONSTANT | 61 |
| GUARDED | 114 |
| UNREACHABLE-ZERO | 35 |
| REACHABLE-CRASH | 1 |
| Total | 211 |

The only REACHABLE-CRASH site is the bank chart's 0x415392; Fix Vanilla Game Bugs fixes it (`InstallBankChartFix` in `native/vf1fun/vf1fun.cpp`, proved by `tests/test_bank_chart_fix.py`). No other site needs a fix.
