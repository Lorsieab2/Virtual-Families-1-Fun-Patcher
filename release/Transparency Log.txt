What this patcher does
----------------------
- Verifies the selected vanilla Virtual Families folder. It must hold
  Virtual Families.exe, Assets, Images, Sounds, fmod.dll, SDL2.dll, SDL2_image.dll,
  and Virtual Families.exe must be the official version 1.01.00
  (SHA-256 5db828c3f53c68696c18719aec0eb114be3fd4458ae2cbf185d8d4ef7eca4487).
- Creates a separate, clearly labeled modded game folder. The vanilla game folder is only read.
- With a vanilla folder selected, Enable/Disable Patches rebuilds a recognized modded folder from the
  vanilla folder. With only a modded folder selected, it reconfigures that folder in place.
- Backs up every file it will replace or delete before writing, and records every file it will create,
  so Restore Backup can put the folder back exactly.
- Writes machine-readable success/failure logs.
- Dry Run (Validate Only) checks the vanilla folder, the executable, the patch and the payload files,
  then stops before creating backups, creating the modded folder, or writing any game file.
- Payload files are read-only/copy-only: the patcher never writes into payload/.

What this patcher does not do
-----------------------------
- Does not inject code into a running game or edit process memory.
- Does not use obfuscation, packers, or admin-only install locations.
- Does not launch the game.
- Does not alter any save. The modded game keeps its own save folder.

The executable patch
--------------------
- The modded executable is the vanilla Virtual Families.exe plus two new sections:
  .vf1fun (read + execute), a small loader, and .vf1fud (read + write), its state.
  No page is both writable and executable.
- Two existing values change so the game enters the loader: the call at 0x4497e6 (end of the
  store screen's constructor) and theGame's Init vtable slot at 0x4b5e14. The PE checksum is
  updated. Nothing else in the original image changes.
- The loader loads "Virtual Families 1 Patcher Files\vf1fun.dll" by full path. If it is missing, the game runs
  exactly as normal.
- The modded executable is named "Virtual Families - Modded.exe". Its name never contains "patch": Windows treats
  such names as installers and asks for administrator rights.

Copy Player Slot (Tools tab, only when you use it)
--------------------------------------------------
- Only while the game is closed. Into any slot but the family's own: one with no Virtual Families<N>.ldw is
  empty, as the game sees it; one that holds a family is replaced only after you answer Yes.
- First copies the whole save folder into Backups\Backup <date> (before copy).
- Then moves everything already in that slot (a replaced family's files, or what a deleted family left) into
  Backups\Replaced by copy <date> - Save <N> - <old name>\, keeping their paths. Never deletes them.
- Writes the copied slot's files, each through a temporary file beside it, then reads it back:
  Virtual Families<N>.ldw (and <N+20>, <N+40> when the family has them) with the new family name,
  Virtual Families 1 Patcher Data\Slot <N>.ini, ...\Children\ and ...\Outfits\Virtual Families<n>.ldw.dat,
  and Virtual Families 1 Patcher\Save <N>\ (the Family History log, with one Family Copied record, and the
  Family Tree files).
- Changes in Virtual Families0.ldw only the new slot's name and its in-use flag, last.
- Never writes the family it copies or any other slot. If anything fails, every file is put back.

Settings and defaults
---------------------
- Main Patches (green), Optional Patches (black) and Experimental (red), as in the patcher window.
- Experimental settings are off by default and Enable All (or --enable-all) leaves them off:
  Experimental: not yet tested in a running game. Back up your saves before using it.
- FixVanillaGameBugs [on] (main): Fix Vanilla Game Bugs
  Keeps a brand-new family if the game is closed without quitting (in the original game the last save was from before the adoption until its next autosave, every 10 minutes). In the Power Failure event, choosing to keep the food now says the food was not ok when people really get sick (the original game always said it was fine). An age set by a cheat no longer becomes the Oldest Villager record: the record only rises when a villager ages into it. A family with a dog is now offered the Pet Turtle in the store (the original game checked for a dog instead of a turtle, so with a dog the turtle never came, and with a turtle it still did). Each outfit bought keeps its own picture in the tray and puts on that outfit (in the original game every Male Outfit, or every Female Outfit, in the tray showed and put on the last one bought); the pictures are kept beside each save, so old saves load as before.
- OlderVillagerMortalityCurve [on] (main): Older Villager Mortality Curve
  Replaces only the annual old-age death roll with a calibrated curve that accelerates past effective age 110. Active food groups still subtract 0-4 effective years. No hard maximum age.
- PrivateRomanticTime [on] (main): Private Adult Romantic Time
  A married opposite-sex couple at six children can still have private romantic time when one is dropped on the other (the original game refuses with "They have enough kids already!"). Like the Virtual Families 2 patcher, a couple that cannot conceive (same-sex, or six children) is also never made to wait "It is too soon to try to make a baby again" after an attempt, and the action reads "Having private adult romantic time". No baby is possible for them.
- UpTo28Children [off] (experimental): Up to 28 Children
  Lets one generation have up to 28 children instead of 6. Only the first 6 children appear in the Family Tree, exactly as before; every child, including the 7th to the 28th, can be chosen to inherit the house in Next Generation. Twins and triplets never take a family past 28: with 27 children a twin or triplet pregnancy has one baby, with 26 a triplet pregnancy has two, and at 28 no more babies come (the normal twin and triplet chances are unchanged while there is room). Children 7 to 28 are remembered in a small file beside each save (the Virtual Families 1 Patcher Data\Children folder in the save folder); the save file itself is not changed. Virtual Families 1 natively keeps up to 6 children per generation in its Family Tree, and a household holds at most 30 villagers (2 parents and 28 children). This patch keeps children 7 to 28 in a separate file beside the save, so they never overwrite Family Tree entries; storing more than 6 children in the Family Tree itself would overwrite its entries and glitch the game. Experimental: not yet tested in a running game. Back up your saves before using it. Installs its own small DLL, vf1kids.dll, in the Virtual Families 1 Patcher Files folder; unticking the setting removes it.
- FamilyHistory [on] (main): Family History Log
  Writes a Family History log of every family event, as it happens, in the Virtual Villagers Fun Patcher's record layout and the game's own words: conceptions, births (twins and triplets, with both parents), deaths with their cause and age, marriages and remarriages (the current spouse, the earlier one and why they left), Divorce Spouse, everyone who joins (Adopt Outside Child, The Little Visitor, Spawn Child, Adopt New Person) or leaves home (college, Boarding School, The Talent Scout), Next Generation and its heir, a new family, Start Over, Evict Family, Roll the Dice, and every Random Event as an Email Event or a Popup Event by the subject line or title the player sees. The Family Tree Maker reads it for what the save forgets. Each save slot has its own log beside the save (Virtual Families 1 Patcher\Save N\Logs\Family History). A family that already exists gets what its Family Tree holds, marked "backfilled, no date", once. A new family or Start Over clears that slot's folder (a Backups folder in it is kept). The save file itself is not changed. Not yet tested in a running game. Installs its own small DLL, vf1logs.dll, in the Virtual Families 1 Patcher Files folder; unticking the setting removes it.
- RenderUnicodeInGameFonts [on] (main): Render Unicode with In-Game Fonts
  Lets the game take and show any letter or symbol in Unicode: accents (French, Turkish, Polish, Vietnamese...), Greek, Cyrillic, Japanese, Chinese, Korean, Cuneiform, emoji and the rest. Typing in the game's own name boxes accepts every character the keyboard gives (accent keys, dead keys, Alt codes and an input method's text), and backspace deletes a whole character. Every piece of text is drawn with the game's own fonts: the game's own letter when it has one; otherwise a patcher-made letter in that font's style (accented letters are built from the game's own letters and accents); otherwise a letter Windows draws on the spot in the font's size, weight and colour (Segoe UI, then Segoe UI Historic, Symbol and Emoji, the Japanese, Chinese and Korean fonts, Nirmala UI, Ebrima and others); otherwise a small box. Names are kept in the save as UTF-8 inside the game's own name fields, which are not made any bigger: a name is cut only between whole characters, and a letter beyond A-Z takes 2 to 4 of a field's bytes (a family name holds 19). Old saves read exactly as before. The stock game, or the game with this setting off, still loads, shows and saves such a save without harm, but shows each accented letter as two or more other letters (for example "Zoë" as "ZoÃ«"). Installs its own small DLL, vf1text.dll, and the patcher-made letters (the Unicode Text folder) in the Virtual Families 1 Patcher Files folder; the game's own art is not changed, and unticking the setting removes them.
- AllowOlderPregnancies [on] (main): Allow Older Pregnancies
  Optional patch: preserves normal fertility behavior below age 50, then allows a small pregnancy chance when either parent is 50 or older. The stock Next Generation flow also becomes available when the oldest living person reaches age 60, provided there is a surviving child.
